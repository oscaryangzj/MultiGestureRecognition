# 决策与待确认事项

这里只记录选择与状态；完整流程及接口见 [README.md](../README.md)，实际文件修改见 [CHANGELOG.md](../CHANGELOG.md)。

## 已确定

- 摄像头识别分静态 State、一次性动作和周期性 waving。一次性事件建模参考 [Meta 项目](https://github.com/facebookresearch/generic-neuromotor-interface)及[论文](https://www.nature.com/articles/s41586-025-09255-w)，摄像头特征分别设计。
- 四段验收顺序为 MediaPipe + State → 一次性 Action 模型 → 一次性 FSM → waving。第一段官方模型已由用户实际试用，第二段模型已训练、真实在线效果待验收；下一轮已规划一次性 FSM、waving 数据与四通道模型、waving FSM 三个交付。
- 当前 State 接 Google 官方 Gesture Recognizer，保留 closed/opened/thumb_up 三路真实分数及 21 点 [21,2]；自训练 MLP 的独立 Sigmoid + BCE 流程保留作对照。State 没有 NULL 输出。
- 第二段只识别 open_hand（握拳→完整张开）与 close_hand（完整张开→握拳），起点为开始离开稳定原手型，完成点为首次清楚达到目标手型。保持手型期间不重复产生动作。
- Action 当前输入为 54 维：原 49 维输入再加四指 PIP 与拇指 MCP 的 5 个三维夹角。掌心仍取 0、5、9、13、17 点中心，绝对位置只用于差分，不输入模型；局部坐标修正宽高比，按 wrist→middle MCP 缩放、对齐掌轴并统一左右手局部方向。速度、加速度和腕部角速度保留相机方向。目标为两个独立的短事件脉冲，使用 BCE。角度模型已用 MPS 重新训练；5 个验证 session（2 个正样本）上 40/40 个事件命中、无误报，含镜像评估也为 40/40。该验证规模有限，仍需在线使用确认泛化效果。
- 按用户要求试用 Meta 离散手势小模型的 Conv1d、三层 LSTM、LayerNorm 与 dropout 组合；摄像头卷积时间尺度按 30 Hz 调整。原 49 维输入及模型结果保留为对照；新 54 维模型使用独立输出目录。
- 模型时间轴统一重采样；二维/三维 21 点和 State 分数插值后再计算特征。线上线下共用等待右侧观测的插值规则，不跨缺手补手，不将 IGNORE 插值成监督；原始录像和人工标注帧保留，完成点使用原始时间，评估延迟计入插值等待。
- 训练窗口采用 8 秒、stride=5 个重采样时间步；按 session 划分后裁窗，窗口起点避开动作，截断事件历史的延迟正标签屏蔽。
- 负例输入按任务和人工排除区间切段，PREPARE 不进入插值、运动差分或 LSTM 历史。任务起点重置特征历史，片段内计算后裁窗；不根据损失掩码删输入，初始未监督帧仍作为历史。标准验证使用相同边界，整录像连续推理单独作对照。
- Action 正负例分开录制，通过 `--plan action` 选择类型。正例输入开合组数，默认从张开开始，握拳/张开自然交替；每次提示只做一次动作，随后保持刚完成的手型。保持时长随机变化；预览可练习，练习不保存。
- 负例保留张开时移动/转腕、握拳时移动/转腕、局部手指活动，加入中指/无名指/小指伸出后回到握拳，以及张开手腕上下摆，共五项。START 前选择一项，每个新 session 采所选任务 30 秒，之前准备 3 秒；选择和实际时长保存在 session。准备期 IGNORE；真正任务范围经人工审核后才成为背景，意外完整开合必须记录真实事件。新采集暂不设置静止握拳和静止张开负任务；两种手型只作准备姿势，历史 session 沿用各自保存的采集计划。
- 正例按提示和官方分数/关键点形变提出起止候选，人逐个确认或调整。负例逐任务播放检查、确认背景，必要时在同一任务内手工记录多个真实事件。确认自动进入下一项，取消整个动作机会/任务；所有提示确认或取消后 session 完成审核，不再用整段 REVIEWED 开关。
- 正例动作前、动作过程中、完成帧直到脉冲前以及 HOLD 的可靠有效帧监督全零，完成点后的短脉冲才监督相应类为 1；负例已确认任务的可靠背景同样全零。缺手、取消和待确认均 IGNORE。正例取消范围包含后续 HOLD、回看与可能延迟的脉冲；负例准备期不补背景。
- 正负 session 在 train/val 列表中共同训练，纯负 session 不要求正事件；每个 split 整体需两类有监督事件。归一化只使用训练集有监督有效帧，正负窗口共同随机打乱，不规定固定混合比例。
- 每轮按完整验证 session 的 macro 事件 F1 选模型，并列依次选低误报/分钟、低平均绝对延迟、低 BCE；同时记录真实事件与背景监督量。事件评估包括负例，缺手和 IGNORE 不计入误报率时长。
- 在线 Action 与离线评估按 checkpoint 复用对应的因果特征、训练归一化和固定长度滚动上下文，每帧输出独立 Sigmoid 概率。在线试用的检测计数参考 Meta 的阈值上穿与短去抖，不等待整段未来分数取峰；一次性动作 FSM 与正式事件接口仍在第三阶段验收。
- session 使用 `target_model: state/action`，Action 另记 `sample_type: positive/negative` 与 `kind: one_shot/background`；一次性动作和 waving 都属于 action。姓名、练习/组数/轮数、实际顺序与准备/动作/保持时长保存在各 session。`--plan state/action` 已实现，periodic 留到第四段。
- State 采集保持随机顺序，各手型组数分别输入；State 只确认稳定起点，类别/终点取 prompt，REST、缺手、未确认或取消的帧 IGNORE。
- 缺手不喂全零特征、不监督。短缺手跳过并保留历史，连续缺手后重置 LSTM、差分及角度历史。训练 padding 带掩码；用户录完后指定训练/验证 session。
- waving 用张开手、掌心大体朝向摄像头；腕部或肘部摆动均可。左右方向原子事件在向一侧运动后观察到折返时完成，区间内用 PCA 生成初稿后人工调整。
- waving 首次收到两个相反方向事件触发，随后等待预期方向并续期，300 ms 未等到下一事件退出。第四段再扩展方向事件通道。

## 逐指三维角特征（已实现，待对比验收）

- 用户确认先试三维逐指弯曲角，用于加强真实开合的证据；计算定义和数据流程见 [README](../README.md) 的“三维逐指弯曲角”章节。代码与初轮训练已完成，待真实在线验收。
- 使用同一 MediaPipe 识别结果的 world landmarks；保留原二维 landmark、相机方向的运动量及官方 State 分数。首轮加入角度的对比保留加速度，上轮去加速度结果不作为 waving 的通用特征结论。
- 用户明确每根手指只取一个角，不增加手指角度变化量：共 5 维，保留加速度时输入为 54 维。代表关节为四指 PIP、拇指 MCP。时序变化由现有 CNN + 三层 LSTM 学习；不增加手指角速度、角加速度、辅助分类器或硬门槛。
- 代表关节是否足以表达开合，以及三维角度在不同朝向/左右手下的稳定性仍需验证。新特征是否作为默认输入由真实事件召回、负例误报和延迟决定，尚未确定。

## 下一轮候选方案（文档规划，尚未实现）

以下建议供下一轮确认和验证，未确认项不视为实现要求。流程、交付顺序和验收操作见 README。

### 一次性 FSM 与公共事件接口

- 先采用每通道“允许触发 / 已触发”两态：上穿触发阈值产生一个事件，高分保持时只保留已触发状态；回落到复位阈值后重新允许触发。首轮触发/复位均用现有 0.5，保留 0.05 秒短去抖；若阈值抖动产生重复，再对比较低复位阈值的滞回效果。这些值在实施时由 config.yaml 管理。
- 首轮不以官方 opened/closed 分数作为动作输出的硬门槛，也不强制所有开合事件严格交替；官方分数仍作为模型输入和回看证据。否则低 State 分数或一次漏报会阻止后续合法动作。
- 同帧互斥冲突建议按触发分数择高：开合为一组、左右方向为另一组；完全同分则该组不输出，记录冲突。短去抖按组处理，让开合与方向事件可以在同一时刻存在，避免四通道共用冷却时间时互相吞掉。
- 建议原子事件字段为 `label/time_seconds/score`，最终动作字段为 `label/time_seconds`；时间是当前推理流程的经过时间，组合层另输出 `waving_active`。首次进入 waving 只上报一次 `waving`，持续时更新活跃状态；退出先通过活跃状态表示。是否另需退出事件由用户确认。

### waving 候选标注与建模

| 项目 | 首轮建议 |
| --- | --- |
| 代表位置 | 五个指尖 4、8、12、16、20 的图像坐标中心；宽高比修正后投影，保留腕部和肘部摆动的整体位移 |
| 方向命名 | 原始图像 x 正向为 left_to_right；镜像预览只转换显示说明，训练镜像交换两个方向目标与掩码 |
| 主轴检查 | PCA 主轴与水平夹角的候选上限 45°，避免上下摆被草稿算法当成左右 waving |
| 平滑 | 重采样后因果 3 点均值；不通过未来轨迹将折返确认帧提前 |
| 幅度 / 反向确认 | 按区间内中位手掌尺度归一化；首轮候选为单程位移至少 0.3 个尺度，反向位移至少 0.05 个尺度且连续 2 个时间步。尺度取 wrist→middle MCP 距离 |
| 事件完成点 | 满足反向证据的确认帧；物理极值另作回看参照。确认后的方向事件仍沿用短延迟正脉冲 |
| 模型 | 首轮沿用 54 维与现有 CNN + 三层 LSTM，输出扩为四个独立 Sigmoid；新模型使用独立目录 |
| State 约束 | 首轮通过张开手的正例、握拳/局部开指等负例学习方向事件，不先加官方 State 的硬阈值过滤 |

幅度、平滑、主轴倾角和反向确认均是待验证初值，实施时加入 config.yaml。PCA 只用于人工区间内的离线草稿；有明显缺手或方向不明时分段修订。

旧数据新增方向通道的监督需人工审核：原开合监督沿用，未知方向范围为 IGNORE。张开手移动/转腕的旧负例先排查真正 waving，再决定方向背景或正事件；不将未标 waving 等同于方向负例。建议新增 `direction_reviewed_intervals` 明确两个方向通道的已审核范围；它与真正动作范围 `waving_intervals` 分别保存。已审核范围内按可靠背景规则生成零目标、按方向完成点生成正脉冲，原有缺手/取消/准备期的 IGNORE 继续生效。

### 首轮采集建议

- 正例分左右手 × 腕部/肘部四种组合。每种先录 2 个训练 session、1 个验证 session；每条提示 5 段 waving，每段随机 4–6 秒，准备/休息初值各 2 秒。共 40 段训练、20 段验证；时长与实际顺序保存在各 session。快慢速度分散在真实段落中，不复制周期扩数据。
- 负例复用现有按任务选择、每条 30 秒的交互，重点补上下摆、握拳左右摆、单次侧移/一次折返、手进入/离开画面；已采的三指活动同样检查。初轮每类建议 2 条训练、1 条验证，可从已有录像中补审核。暂不新增独立静止手型任务。
- 采集速度先覆盖自然快慢，并统计真实半周期。使用不同次录制的 session 划分，不把同一录像的相邻窗口分到训练和验证。
- 首轮数据量用于跑通流程；负例验证总时长不足时只能报告误报次数与观测时长，不能用短录像的零误报证明长期稳定。

### waving FSM 规则候选与时间限制

- 已定规则保持：两个相反方向原子事件触发，之后严格等待预期方向续期，活跃超时为 300 ms。
- 首次配对期限建议单独配置，首轮候选也为 300 ms。等待第二次时的同方向重复不刷新候选时间；活跃时的非预期方向同样不续期。超时先回到空闲，迟到事件可作为下一段的第一个候选。
- 建议在当前时间达到期限时先处理超时，再处理该时刻输入；事件正好落在期限上按超时后的新候选处理。此边界规则需确认并在固定时间线验收。
- 短缺手期间保持计时；连续缺手重置模型历史和事件解码历史，waving 按已有超时规则退出。停止产生新概率时也要推进超时。
- 300 ms 是事件间隔上限。稳定摆动约要求半周期小于 300 ms、频率高于约 1.67 Hz；慢 waving 可能在段内反复退出。先检查真实半周期和预测事件间隔，再确认是否调整活跃超时或加入速度适配；本轮规划不变更已定值。
- 普通张开手左右往返平移与肘部 waving 可能具有相同观测轨迹。建议连续左右往返且手型满足定义时都计 waving，单次移动作为非 waving；若需按意图区分，应先定义额外可观察证据。

### 首轮验收目标建议（数值待用户确认）

| 验收层 | 候选目标与计分范围 |
| --- | --- |
| 确定输入的解码/FSM | 分数和事件时间线的预期输出全部一致，覆盖重复、冲突、超时边界、缺手及重新开始 |
| 开合回归 | 当前 40 个真值逐条核对；新连续录像逐类召回 ≥95%、误报 ≤0.5 次/分钟、P95 触发延迟 ≤0.5 秒 |
| 方向原子事件 | 左右分别报告，建议 precision/recall 均 ≥95%；报告确认帧相对物理折返的标签延迟及实际触发延迟 |
| waving 首次触发 | 至少 20 段独立验证、按段召回 ≥95%；从第二个真值相反事件算 P95 延迟 ≤0.5 秒 |
| waving 持续/退出 | 每段一次开始事件；活跃覆盖率建议 ≥90%，段内错误退出/重新进入全部列出；固定事件输入的退出时间符合超时配置 |
| 背景误报 | waving 最终误报建议 ≤0.5 次/分钟，尽量累计至少 5 分钟独立有效背景；报告所有额外开始事件 |

调阈值使用验证录像；选定后冻结参数，另录独立验收录像。左右手、腕部/肘部及快慢结果分开报告，失败的慢动作不能因 300 ms 规则而从统计中删掉。线上时间尺度按实际经过时间计算，延迟与活跃覆盖率不会由视频帧数换算替代。

## 已实现的初值，需验证数据调整

- MediaPipe 0.10.35 为已验证的本机版本，Tasks Vision 同步逐帧接口；推理当前用 CPU delegate，模型训练用 MPS。
- Action 采样率初值为 30 Hz，完成后 100 ms 开始监督、持续 150 ms；用原始完成时间生成脉冲，宽度通过验证选择。
- 有效背景需要连续可见手 3 帧；连续缺手 3 帧重置。短缺手恢复后按实际时间差计算差分。
- Conv1d 输出 128 维、kernel=3、stride=1；单向 LSTM hidden=128、3 层；卷积后和 LSTM 层间 dropout=0.1，卷积后与 LSTM 输出各有 LayerNorm。训练窗口从零 hidden state 开始，评估同长度滚动窗口重算。学习率参考 Meta 小模型加入 5 轮 warmup 和每 25 轮减半；参数以 config.yaml 为准。
- 本机 MPS 的原生多层 LSTM 内置 dropout 在训练后会使评估与独立加载不一致；三层实现采用单层 LSTM 堆叠和显式层间 Dropout，保留 Meta 的结构与 dropout 位置。
- 候选用 State 分数阈值 0.5、稳定 3 帧、回看 15 帧、局部形变阈值 0.04、形变确认 2 帧。这些只生成草稿，人确认后才监督。
- 正例模板默认 10 组，练习 2 组，每次动作提示 3 秒，保持时长均匀随机 0.8–2.5 秒，开始后准备保持 2 秒。负例每条选择一项、任务 30 秒，之前准备 3 秒；各 session 可调整采集参数。
- 评估阈值与匹配容差为可调初值；评估峰值匹配属于第二阶段，不定义最终产品事件上报。
- 在线检测沿用阈值 0.5，跨类别去抖初值为 0.05 秒，参考 Meta 开源实现的非 release 事件规则；配置在 `inference` 中。开合手不使用 Meta 的 index/middle release 特例。

## 待确认 / 待真实数据验证

- Action 候选的起点/完成点质量，窗口长度、脉冲宽度、背景与缺手阈值、模型大小、正例权重、事件容差及可接受误报/延迟；负例任务和时长是否覆盖真实误报场景。

- 单手场景下漏检、左右手与换手的覆盖；官方 State 对非目标手型和不同朝向的误报边界。
- 下一轮上述候选方案中的解码复位/冲突规则、PCA 候选参数、采集量及验收数值目标。
- waving 普通往返平移的正负定义、首次配对期限、300 ms 活跃超时对自然速度的覆盖，以及是否需要独立退出事件。
